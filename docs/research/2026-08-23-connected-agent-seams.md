# Connected Agents: current JobOS agent and profile seams

**Date:** 2026-08-23

**Ticket:** [#102 — Map the current JobOS agent and profile seams](https://github.com/cobibean/job-os/issues/102)

**Wayfinder map:** [#100 — Connected Agents and Codex](https://github.com/cobibean/job-os/issues/100)

**Repository baseline:** `c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8` (`origin/main` when this research branch was created)

## Scope and locked contract

This is repository reconnaissance, not an implementation design. It records the seams that a later Connected Agents plan must extend rather than replace.

The locked product contract is:

- reusable Connected Agents, initially multiple Hermes connections and one ChatGPT/Codex connection;
- agent connections and credentials are installation-global, while each JobOS Profile owns a default agent;
- permissions are global in V1;
- each agent owns a V1 default model, with GPT 5.6 Sol medium preferred where the provider supports it;
- a chat permanently pins one agent connection and one model at creation;
- exactly five active chats total remains the invariant;
- every supported agent receives the full JobOS MCP/tool surface;
- existing Hermes setup and old chats migrate;
- Connected Agents receives a dedicated settings page;
- setup works across devices; disconnected chats remain readable but locked;
- the public core remains source-first and local-first, and external agents remain optional adapters. The repository rule is explicit: public defaults must use loopback/local SQLite and optional integrations must stay behind configured adapters with capability-based unavailable errors ([`AGENTS.md` L3-L11](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/AGENTS.md#L3-L11)).

## Executive findings

1. **The durable chat core is already provider-neutral at its narrowest boundary, but composition is single-Hermes.** `AgentGateway` and `AgentGatewayFactory` are protocols, yet the factory key is only `conversation_id`; no durable agent-connection or model identity exists ([`agent_gateway.py` L30-L56](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/agent_gateway.py#L30-L56)). API composition creates one process-global Hermes factory from one URL/token/CWD tuple, or an offline factory ([`app.py` L603-L634](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/app.py#L603-L634)).
2. **A chat already has a durable remote-session key, but not immutable provider/connection/model ownership.** The `conversations` row stores `stored_session_id` and recovery/isolation state; the dispatch path always asks the currently composed gateway to resume it ([`state_store.py` L704-L716](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/state_store.py#L704-L716), [`conversations.py` L424-L475](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/conversations.py#L424-L475)).
3. **The five-chat invariant is deliberately duplicated across storage, API schemas, main-process normalization, renderer behavior, and tests.** It is currently five per `owner_device_id`, not five per installation profile independent of device ([`state_store.py` L1940-L1958](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/state_store.py#L1940-L1958)). This ownership detail must be reconciled with “five chats total” and multi-device access without changing the count.
4. **JobOS already exposes 44 MCP tools, 32 explicitly conversation-scoped.** The correlation fence spans the Hermes prompt, typed MCP arguments, the MCP client context, API middleware, active-turn device routing, and durable continuation identity. Full tool parity means preserving this whole surface and its fences for every connector, not merely forwarding chat text.
5. **Installation profiles already establish the correct global/profile split for storage, but Connected Agent persistence does not yet exist at the installation layer.** The installation-global registry selects one anchored or managed profile; managed profiles receive separate SQLite/jobs/artifact/evidence roots and separate Electron partitions. Device/MCP secrets and runtime configuration sit above that split. Existing “connected agents” tables are Career Profile authorization records inside each profile database, not reusable provider connections.
6. **Current settings and avatar concepts are singleton-oriented.** Settings is one modal containing theme, Career Profile agent-editing controls, one global “Agent icon” preference, and diagnostics. The only bundled avatar is Ninja, and the preference is one renderer `localStorage` key—not connection metadata.
7. **Health is an aggregate singleton projection.** `/v1/health.agent` reports `online`, `connecting`, or `offline` if any conversation gateway has that state; it cannot identify individual connections or distinguish “chat locked because its pinned connection is disconnected.”
8. **Migration and installed-app proof conventions are strong and directly reusable.** Ordered transactional SQLite migrations, installation ownership fencing, generated OpenAPI drift checks, exact packaged/installed artifact identity, restart/readback, synthetic isolated profiles, and real rendered-control exercise are existing invariants.

## 1. Conversation persistence and ownership

### Current durable shape

- Migration 16 replaced the former singleton chat with `conversations`, `conversation_turns`, and `conversation_events`. It preserved the old conversation as `Session 1`, including its `stored_session_id`, then copied all turns and events while retaining event IDs ([`state_store.py` L690-L734](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/state_store.py#L690-L734), [`state_store.py` L736-L813](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/state_store.py#L736-L813)). This is the existing precedent for migrating old chats without rewriting transcript history.
- Each active conversation persists position, title, one remote `stored_session_id`, recovery markers, isolated-session markers, timestamps, and archive state ([`state_store.py` L704-L716](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/state_store.py#L704-L716)). Migration 17 added `owner_device_id`; migration 18 made active positions unique within that owner ([`state_store.py` L816-L837](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/state_store.py#L816-L837)).
- Migration 19 moved selected-job and document-view state into each conversation, so chat context is already durable and chat-scoped ([`state_store.py` L840-L857](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/state_store.py#L840-L857)).
- `ConversationStore` is explicitly scoped to exactly one conversation. It reads and compare-and-swaps the remote stored session and separately tracks isolated/recovery sessions ([`conversation_store.py` L53-L91](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/conversation_store.py#L53-L91), [`conversation_store.py` L93-L166](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/conversation_store.py#L93-L166)).
- User messages, sanitized context, turns, and transcript events are committed before remote dispatch, with idempotency and one-active-turn checks ([`conversation_store.py` L168-L240](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/conversation_store.py#L168-L240), [`conversation_store.py` L327-L410](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/conversation_store.py#L327-L410)). Snapshot reads come entirely from SQLite events and current turn state, so transcript readability does not depend on a live provider ([`conversation_store.py` L899-L948](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/conversation_store.py#L899-L948)).
- `ConversationManager` starts one service and one gateway per active conversation, keeps those services in an ID-keyed registry, and recreates them at API startup ([`conversation_manager.py` L34-L73](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/conversation_manager.py#L34-L73), [`conversation_manager.py` L87-L95](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/conversation_manager.py#L87-L95)).

### Locked-contract reconciliation

- **Already aligned:** transcripts are local and durable; each chat already owns one remote session key; recovery is chat-scoped; old singleton-chat migration preserved the original session and transcript.
- **Missing durable invariants:** no provider kind, installation connection ID, immutable chat model, or creation-time connection/model snapshot exists in the conversation schema, API response, gateway factory call, desktop contracts, or renderer state. A stored Hermes key is therefore interpreted by whichever single gateway is currently composed.
- **Disconnected behavior mismatch:** the renderer keeps durable transcript items visible, but `canSend` gates only draft/turn/restore/operation/API state—not the chat gateway’s `offline` state ([`AgentPanel.tsx` L73-L83](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/apps/desktop/src/renderer/components/AgentPanel.tsx#L73-L83)). The UI currently says “Send to reconnect the agent” when the gateway is not online ([`AgentPanel.tsx` L315-L344](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/apps/desktop/src/renderer/components/AgentPanel.tsx#L315-L344)); the locked contract instead requires a disconnected pinned chat to be readable and locked.

## 3. Gateway construction and Hermes session lifecycle

### Provider-neutral seam

- `AgentGateway` owns connection state, start/close, create-or-resume, submit, event streaming, interrupt, and recovery. `AgentGatewayFactory` promises one isolated gateway per active conversation ([`agent_gateway.py` L30-L56](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/agent_gateway.py#L30-L56)).
- Offline behavior is a first-class adapter with stable `Agent gateway is not configured` failures ([`agent_gateway.py` L59-L92](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/agent_gateway.py#L59-L92)). This is the local-first optional-adapter fallback to preserve.

### Current single-Hermes composition

- `Settings` has one Hermes dashboard URL, token, JobHunter CWD, and timeout ([`settings.py` L47-L71](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/settings.py#L47-L71)). Environment composition reads exactly one `JOBOS_HERMES_DASHBOARD_*` tuple ([`main.py` L44-L77](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/main.py#L44-L77)).
- `create_app` builds one `HermesGatewayFactory` if and only if URL, token, and CWD are all configured; otherwise all conversations use `OfflineAgentGatewayFactory` ([`app.py` L603-L634](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/app.py#L603-L634)).
- The factory captures shared URL/token/CWD and creates independent WebSocket adapters, but ignores the passed `conversation_id` ([`hermes_adapter.py` L171-L186](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/hermes_adapter.py#L171-L186)).
- The Hermes adapter requires loopback, hard-codes/validates profile `job-hunter`, resolves the approved CWD, and strips tokens from URLs/repr ([`hermes_adapter.py` L189-L240](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/hermes_adapter.py#L189-L240), [`hermes_adapter.py` L242-L252](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/hermes_adapter.py#L242-L252)). Multiple Hermes profiles/connections are therefore not representable today.

### Hermes create/resume and recovery invariants

- Resume sends `session.resume` with stored session ID, profile, source `jobos`, and `close_on_disconnect=false`; only Hermes RPC code `4007` falls back to `session.create` ([`hermes_adapter.py` L331-L362](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/hermes_adapter.py#L331-L362)).
- Create sends profile, source, resolved CWD, and `close_on_disconnect=false` ([`hermes_adapter.py` L448-L457](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/hermes_adapter.py#L448-L457)).
- Returned profile and CWD must match before the session is trusted; dispatch refuses an unverified attachment ([`hermes_adapter.py` L427-L478](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/hermes_adapter.py#L427-L478)). This fail-closed isolation check is a connector invariant, not Hermes-only incidental behavior.
- Prompt submission uses the live Hermes session and accepts only `streaming`, `accepted`, or `queued` acknowledgements ([`hermes_adapter.py` L480-L503](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/hermes_adapter.py#L480-L503)). API restart recovery reattaches the durable stored session, verifies it, interrupts the remote operation, then settles or quarantines the local turn ([`conversations.py` L147-L205](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/conversations.py#L147-L205), [`hermes_adapter.py` L521-L528](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/services/api/jobos_api/hermes_adapter.py#L521-L528)).

**Locked-contract gap:** neither the gateway protocol nor Hermes RPC payload contains a JobOS model selection. There is no current repository seam for per-agent defaults or immutable per-chat models; those facts must become explicit contract/persistence inputs rather than mutable process defaults.

## 7. Migration invariants

- Stop and restart both API and app against the same disposable SQLite/Electron data before accepting persistence ([`career-profile-first-slice/README.md` L9-L12](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/docs/acceptance/career-profile-first-slice/README.md#L9-L12), [`career-profile-first-slice/README.md` L67-L77](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/docs/acceptance/career-profile-first-slice/README.md#L67-L77)).
- For a real installed candidate, install at `/Applications/JobOS.app`, run `codesign --verify --deep --strict`, hash installed `app.asar` and package ZIP, prove installed `app.asar` matches the candidate, and exercise the installed Electron window ([`career-profile-live-cutover/README.md` L30-L43](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/docs/acceptance/career-profile-live-cutover/README.md#L30-L43)).
- Acceptance evidence uses synthetic fixtures and isolated app/API/browser/credential roots unless separately approved private acceptance requires sanitized non-repository evidence. Packaged journeys include accessibility and restart/readback, not screenshots alone ([`career-profile-product-experience/README.md` L2-L16](https://github.com/cobibean/job-os/blob/c4a06ce42a3de41aeb87e63ffb5a5c1b9738a4d8/docs/acceptance/career-profile-product-experience/README.md#L2-L16)).

Connected Agents acceptance therefore must eventually prove package identity, installation identity, connection setup, profile default isolation, immutable chat ownership/model across restart and profile/device changes, migration of an old Hermes chat, full MCP capability use, and disconnected readable/locked state in the actual installed app—not only API/unit behavior.

## Boundary to preserve

Connected Agents should extend the existing local conversation authority, profile isolation, MCP fencing, recovery, and verification systems. It should not make Hermes, Codex, OAuth, a private network, or any operator path mandatory for startup; should not move provider-owned transcript authority out of local SQLite; and should not collapse installation connections, per-profile defaults, Career Profile grants, device credentials, and per-chat immutable bindings into one ambiguous “agent” record.
